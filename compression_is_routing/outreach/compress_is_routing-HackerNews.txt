Author here. I'm an independent researcher; this is a short technical report.

I trained an 87M-parameter Transformer autoencoder on code that compresses 512 tokens into 8 latent vectors (64x along the sequence). The decoder never sees the input, only the latents plus a content-free auxiliary signal. Exact-token reconstruction: 99.47% on held-out code, 47.76% on Wikipedia, 0.57% on random tokens (chance is about 0.002%).

The argument: if each expert in a modular system has its own domain compressor, reconstruction error can be the routing signal directly, with no trained gating network, and it's interpretable. New domains get a new compressor while old ones stay frozen, which avoids interference by construction.

What it doesn't show yet: no continual-learning benchmark, fixed 512-token windows lag at domain switches, and interleaved text (prose with code) is a gray zone. Ablations are limited by compute.

There's an 8-minute animated explainer if you prefer visuals: [VIDEO_LINK]
Repo: https://github.com/simonFelix-Ai/compression_is_routing

I'd especially value pointers to prior work on reconstruction-based routing for language, and thoughts on how this compares to using plain LM perplexity as the routing score.
